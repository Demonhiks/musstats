# MusStats — статистика прослушиваний для iPhone

PWA, которая превращает историю прослушиваний в понятную статистику: часы, топ-артисты, календарь активности и карточку «итоги года», которой можно поделиться.

**Живое демо:** https://demonhiks.github.io/musstats/?demo=1

## Что это

Небольшое приложение под iPhone, которое открывается с домашнего экрана как обычное и считает статистику по вашей музыке. Сделано под историю Яндекс Музыки, но понимает и другие источники.

Всё считается в браузере: файлы никуда не загружаются, история лежит в IndexedDB на самом устройстве. Ни аналитики, ни трекеров, ни серверов.

## Что умеет

- **Импорт с автоопределением формата** — ZIP-архив Яндекс ID, JSON, CSV, TSV. Понимает экспорт Last.fm, Spotify (`Streaming_History_Audio_*.json`), русские шапки вроде `Исполнитель;Название;Дата`, Unix-время и даты вида `01.05.2023 18:20`. Повторная загрузка не плодит дубли.
- **Обзор** — часы прослушивания, число артистов и треков, график динамики, топ-артисты, пиковый день, любимое время, серии дней подряд.
- **Топы** — артисты, треки и альбомы за период с долями и полосами прогресса.
- **Активность** — heatmap-календарь как на GitHub, распределение по часам и дням недели, «сова/жаворонок».
- **Итоги года** — карточка 1080×1440, которую можно сохранить в «Файлы» или отправить через системное «Поделиться».
- **Периоды** — 7 дней, 30 дней, 90 дней, год, всё время.
- **Офлайн** — service worker кэширует оболочку, приложение открывается без сети.
- **Демо-режим** — `?demo=1` показывает приложение на сгенерированной истории, ничего не записывая в хранилище.

## Чего здесь нет (и почему)

Это **не** «взломанный Яндекс Музыка» и не клиент для прослушивания. У Яндекса нет публичного API для сторонних клиентов: все сторонние клиенты работают через реверс-инжиниринг внутреннего API `api.music.yandex.net`, что нарушает условия сервиса, приводит к блокировке аккаунта и ломается после каждого изменения на стороне сервиса. Подписку такой клиент всё равно не даёт — без Плюса доступны только короткие превью.

MusStats работает только с официальным экспортом данных и ничего не обходит.

## Откуда брать историю

**Яндекс Музыка.** [Яндекс ID → Мои данные](https://id.yandex.ru/personal/data) → запросить архив → скачать по ссылке из письма. Загружать ZIP можно как есть: приложение само найдёт внутри файл с историей.

> Ограничение на стороне Яндекса: в архив попадает только часть последних прослушиваний (у разных аккаунтов — от нескольких сотен до пары тысяч треков), а имя исполнителя иногда не выгружается. Периодически сохраняйте свою копию через «Настройки → Скачать копию (JSON)», чтобы накапливать историю.

**Last.fm.** [Settings → Data exports](https://www.last.fm/settings/data-exports) → CSV. Дата в Unix-времени — парсер это понимает.

**Spotify.** Аккаунт → Конфиденциальность → «Скачать ваши данные», распаковать архив и загрузить `Streaming_History_Audio_*.json`.

## Установка на iPhone

1. Откройте https://demonhiks.github.io/musstats/ в **Safari** (именно в нём, не в Chrome — иначе не будет кнопки установки).
2. «Поделиться» → **«На экран „Домой“»**.
3. Запускайте с иконки: приложение откроется на весь экран, без адресной строки Safari.
4. Внутри нажмите **«+»** → выберите файл из «Файлов».

Особенности iOS, о которых стоит знать:

- Хранилище PWA может быть очищено системой, если приложением не пользоваться неделями. Держите резервную копию JSON.
- Те же данные видны только в этом приложении на этом устройстве — синхронизации нет намеренно.
- «Поделиться карточкой» работает через нативное меню iOS (Web Share API), в том числе в Instagram и Telegram.

## Локальный запуск

Нужен Node.js 20+.

```bash
pnpm install
pnpm dev       # http://localhost:5173
pnpm build     # сборка в dist/
pnpm preview   # проверить собранную версию
pnpm test      # тесты парсера истории
```

Иконки PWA не лежат в репозитории — `tools/make-icons.mjs` рисует PNG на чистом Node перед каждой сборкой (никаких зависимостей и бинарников в git).

## Деплой

GitHub Actions собирает проект и публикует его на GitHub Pages при каждом пуше в `main` (workflow `.github/workflows/deploy.yml`). Для нового форка достаточно включить **Settings → Pages → Build and deployment → Source: GitHub Actions** и запустить workflow.

## Приватность

Приложение не делает ни одного запроса за данными пользователя: единственная сеть — загрузка собственных статических файлов. История хранится в IndexedDB, экспорт — локальный файл.
